# 架構說明

[简体中文](../Zh-cn/ARCHITECTURE.md) · [繁體中文](ARCHITECTURE.md) · [English](../en/ARCHITECTURE.md) · [返回繁中 README](README.md)

## 為何不需要專案伺服器

模組只負責在玩家用戶端擷取、正規化及顯示文字。翻譯提供者透過統一介面注入，
可以是玩家自行選擇的線上 API，也可以是執行於玩家電腦上的本機服務。專案本身
不會代理聊天內容、儲存玩家資料，也不需要負擔中央伺服器成本。

## 資料流程

1. 版本轉接層在彩現或收到文字元件時擷取可見文字。
2. 隱私權規則判斷該內容是否可傳送至翻譯器。
3. `ProtectedText` 在本機分離玩家名稱、伺服器位址、數字、既有中文及樣式代碼。
4. `LanguageHeuristics` 略過空內容、純數字及已經是目標語言的內容。
5. `TranslationCoordinator` 查詢快取，並合併進行中的相同請求。
6. 翻譯提供者在背景執行緒只處理可翻譯的文字片段；受保護內容不會進入請求。
7. 各片段與受保護內容在本機依原順序重新組合，並於下一影格或下一次彩現時顯示譯文。
8. 任一步驟失敗時繼續顯示伺服器原文。

可選的傳送翻譯使用獨立路徑：平台層取消原始一般聊天訊息，核心背景佇列翻譯並保護
玩家名稱、位址等字面值，完成後再由 Minecraft 主執行緒透過原版聊天入口送出。多個
請求即使並行完成，也會按輸入順序傳送；命令、失敗請求及過長譯文不會被靜默改寫。

## 多版本邊界

`translator-core` 維持 Java 8 相容，且不引用 Minecraft 類別。每個載入器模組只負責：

- 在 Minecraft 文字元件與一般字串之間轉換；
- 擷取各介面及世界文字；
- 在遊戲主執行緒安全地更新顯示快取；
- 載入對應版本的設定介面及按鍵綁定。

因此舊版 Forge 與現代 Fabric 版本可以共用演算法，同時分別產生相容的 JAR。

## 擷取策略

- Fabric 1.20.1、1.21.11、26.1 與 26.2 分別在對應版本的 `DrawContext`／`GuiGraphicsExtractor`
  及 `TextRenderer`／`Font` 最終彩現入口替換顯示副本，
  並於聊天、計分板、Tab、標題、Action Bar 及 Boss Bar 彩現期間記錄內容類型。
- Forge 1.8.9/1.12.2 使用同一個 LaunchWrapper ASM 核心外掛程式，在
  `FontRenderer` 的繪製及寬度計算入口替換字串；聊天 HUD 另有輕量情境，
  用於執行聊天隱私權開關。

預設彩現翻譯不會修改原始網路封包、聊天簽章、Text 元件或伺服器狀態。只有使用者
主動開啟「傳送翻譯」時，一般外送聊天才會以譯文取代，並透過原版入口重新簽章。
若伺服器預先將文字繪製成圖片，或第三方模組完全繞過 Minecraft 字型彩現器，該文字
便不在目前擷取範圍內。

## 安全邊界

- 預設關閉連網翻譯。
- 非回環 HTTP 位址會被拒絕；遠端服務必須使用 HTTPS。
- 線上 API 不跟隨 HTTP 重新導向，連線及讀取都有逾時限制，回應上限為 1 MiB。
- 離線元件下載只接受 HTTPS，並驗證續傳範圍、類型、固定大小及 SHA-256；鏡像失敗時會回退至官方來源。
- 原文快取鍵使用 SHA-256；本機快取只儲存雜湊鍵與譯文，不儲存明文原文。
- API 金鑰不會寫入日誌或打包進發行 JAR。
