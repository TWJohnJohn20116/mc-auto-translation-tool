# 架构说明

[简体中文](ARCHITECTURE.md) · [繁體中文](../Zh-tw/ARCHITECTURE.md) · [English](../en/ARCHITECTURE.md) · [返回简中 README](README.md)

## 为什么不需要项目服务器

模组只负责在玩家客户端捕获、规范化和显示文字。翻译提供者通过统一接口注入，
可以是玩家自行选择的在线 API，也可以是运行在玩家电脑上的本地服务。项目自身
不代理聊天内容、不保存玩家数据，也不承担中心服务器成本。

## 数据流程

1. 版本适配层在渲染或收到文本组件时提取可见文本。
2. 隐私规则判断这种内容是否允许送往翻译器。
3. `ProtectedText` 在本机分离玩家名、服务器地址、数字、已有中文和样式代码。
4. `LanguageHeuristics` 跳过空内容、纯数字和已经是目标语言的内容。
5. `TranslationCoordinator` 查询缓存并合并正在进行的相同请求。
6. 翻译提供者在后台线程只处理可翻译的文字片段，受保护内容不会进入请求。
7. 各片段与受保护内容在本机按原顺序拼回，下一帧或下一次渲染时显示译文。
8. 任一步失败时继续显示服务器原文。

可选的发送翻译走独立路径：平台层取消原始普通聊天发送，核心后台队列翻译并保护玩家
名、地址等字面量，完成后再由 Minecraft 主线程通过原版聊天入口发送。多个请求即使
并发完成也按输入顺序发送；命令、失败请求和过长译文不会被静默改写。

## 多版本边界

`translator-core` 保持 Java 8 兼容，不引用 Minecraft 类。每个加载器模块只完成：

- Minecraft 文本组件与普通字符串之间的转换；
- 各界面和世界文字的捕获；
- 在游戏主线程安全地更新显示缓存；
- 加载对应版本的设置界面与按键绑定。

这使旧 Forge 和现代 Fabric 版本可以共享算法，同时分别生成兼容 JAR。

## 捕获策略

- Fabric 1.21.4、1.21.11、26.1 与 26.2 分别在对应版本的 `DrawContext`/`GuiGraphicsExtractor` 和
  `TextRenderer`/`Font` 最终渲染入口替换显示副本，
  并在聊天、记分板、Tab、标题、Action Bar 和 Boss Bar 渲染期间记录内容类型。
- Forge 1.8.9/1.12.2 使用同一个 LaunchWrapper ASM 核心插件，在
  `FontRenderer` 的绘制与宽度计算入口替换字符串；聊天 HUD 另有轻量上下文，
  用于执行聊天隐私开关。

默认渲染翻译不修改原始网络包、聊天签名、Text 组件和服务器状态。只有用户主动开启
“发送翻译”时，普通出站聊天才会被译文替换，并通过原版发送入口重新签名。若某服务器把文字预先
绘制进图片，或第三方模组完全绕过 Minecraft 字体渲染器，该文字不在当前捕获范围。

## 安全边界

- 默认关闭联网翻译。
- 非回环 HTTP 地址会被拒绝；远程服务必须使用 HTTPS。
- 在线 API 不跟随 HTTP 重定向，连接和读取均有超时，响应上限为 1 MiB。
- 离线组件下载只接受 HTTPS，并校验断点范围、类型、固定大小与 SHA-256；镜像失败会回退官方源。
- 原文缓存键使用 SHA-256；本地缓存保存的是哈希键和译文，不保存明文原文。
- API 密钥不会写入日志或打进发行 JAR。
